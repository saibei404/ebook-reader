# 排版验证样本（test-fixtures）

用于校验墨鱼阅读器在各格式下的**排版布局、字号层级、字体渲染与颜色表现**。
所有文件由 `scripts/gen_test_fixtures.py` 生成（PDF 由 `scripts/make-test-pdf.cjs` 经 Chromium 打印），
内容规格完全一致，便于跨格式对比。

```

├── pdf/   01-排版全要素.pdf      Chromium 打印（A4，中文嵌入字体）
```

## 重新生成与验证

```bash
# 生成全部样本（含 PDF 源 HTML）
python scripts/gen_test_fixtures.py
# 打印 PDF（Chromium，保证中文字体与排版真实）
electron scripts/make-test-pdf.cjs

# 逐份打开验证（截图 + 样式探针写入 test-fixtures/_verify）
MOYU_TEST_READER="md|?testpath=<绝对路径>/test-fixtures/md/01-排版全要素.md" \
  electron .
```

`_verify/<name>.json` 记录每个样本的实测计算样式：

```
正文字号|颜色|字体|字重|行高  例：19px|rgb(232, 230, 227)|Songti SC|w400|lh35.15px
元素计数                      h1/h2/h3/p/table/th/li/pre/quote
颜色样本                      页面中出现的去重色值
```

## 各格式的已知差异（非缺陷，格式能力或引擎限制）

| 格式 | 表现 | 原因 |
|---|---|---|
| DOCX | 字符颜色不显示（红色显示为普通文字） | mammoth 在解析 `word/document.xml` 时不读取 `w:color`（源码无此分支），颜色在进入 HTML 前已丢失 |
| DOCX | 绝对字号不透传（9pt 注释与正文同号） | 同上：`w:sz` 未映射；正文统一走阅读器字号设置（阅读类应用通行做法） |
| DOCX | 段落对齐（居中/右）丢失 | mammoth 不映射 `w:jc` |
| FB2 | 无颜色 | FB2 规范本身无字符颜色标记 |
| FB2 | 表格降级为文本 | FB2 规范无表格元素 |
| PDF / CBZ | 无法用 DOM 探针校验字体/颜色 | canvas 位图渲染，只能目检截图 |
| EPUB | 首屏只渲染当前章 | epub.js `scrolled-doc` 单章渲染，属预期行为 |

## 深色主题对比度适配（本轮修复）

EPUB 内容自带的作者 CSS 常写死深灰字（如 `h4{color:#444}`、`small{color:#666}`）与浅灰底
（`blockquote{background:#f7f7f8}`），在深色主题下几乎不可读。阅读器现在会在渲染每章时：

- 只对**灰阶**颜色（R/G/B 最大差值 ≤ 45）做主题适配：过暗文字改为继承主题前景色；
- 高饱和强调色（红/绿/蓝等）**保持作者原样**，不破坏配色意图；
- 与主题背景冲突的灰阶整块底色改为低透明度中性底，保留层次感。

验证：修复前 `h4`/`small` 行亮度约 #444（在 #111113 背景上对比度不足 2:1），
修复后与正文同亮度（#e8e6e3，对比度约 13:1），彩色强调项色值不变。
